Run PHP faster, without touching the PHP you already have.

Chạy PHP nhanh hơn, không đụng tới PHP đang có.

QHturbo builds PHP from the official source and installs it beside your current PHP. Keep your code as it is with PHP-FPM, or run it in long-lived workers that boot your framework once instead of on every request.

QHturbo build PHP từ mã nguồn chính thức và cài song song với PHP hiện tại. Giữ nguyên code và chạy bằng PHP-FPM, hoặc chạy trong worker lâu dài: framework chỉ khởi động một lần thay vì ở mỗi request.

Build & install

Build & cài đặt

QHturbo installs into /opt/qhturbo/<version> with its own PHP-FPM socket and service. It refuses to write into /usr, /etc or aaPanel's PHP, so your current PHP keeps running.

QHturbo cài vào /opt/qhturbo/<phiên bản>, có socket PHP-FPM và service riêng. Script từ chối ghi vào /usr, /etc hay PHP của aaPanel, nên PHP hiện tại vẫn chạy bình thường.

  3. Connect a site

    Nối một site

    Follow Compatible to serve PHP files through the new PHP-FPM, or Performance to run workers.

Compatible

Point one site at the QHturbo socket /run/qhturbo/php85-fpm.sock (the number follows the version: php74 … php85). Every other site keeps its current PHP. To go back, restore the old line and reload the web server.

Trỏ một site vào socket của QHturbo /run/qhturbo/php85-fpm.sock (số theo phiên bản: php74 … php85). Các site khác giữ nguyên PHP hiện tại. Muốn quay lại, khôi phục dòng cũ rồi reload web server.

Nginx

# inside the site's server { } block, instead of the old fastcgi_pass
location ~ \.php$ {
    try_files $uri =404;
    fastcgi_pass unix:/run/qhturbo/php85-fpm.sock;
    fastcgi_index index.php;
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
}
sudo nginx -t && sudo systemctl reload nginx
curl -sI http://your-site.example/ | head -1     # expect 200; on errors restore the old block

Apache 2.4

sudo a2enmod proxy proxy_fcgi setenvif
# in the site's <VirtualHost>, or in its .htaccess (needs AllowOverride FileInfo):
<FilesMatch \.php$>
    SetHandler "proxy:unix:/run/qhturbo/php85-fpm.sock|fcgi://localhost"
</FilesMatch>
sudo apachectl configtest && sudo systemctl reload apache2
echo '<?php echo PHP_VERSION, " ", PHP_SAPI;' | sudo tee /var/www/your-site/qht-check.php
curl -s http://your-site.example/qht-check.php    # "8.5.x fpm-fcgi" -> it runs on QHturbo; delete the file afterwards

Both were tested on 2026-10-22: Apache 2.4.58 with proxy_fcgi and nginx, on Ubuntu 24.04. If Apache still shows the old PHP version, that server uses mod_php; the site must use PHP-FPM first.

Cả hai đã được test ngày 2026-10-22: Apache 2.4.58 với proxy_fcgi và nginx, trên Ubuntu 24.04. Nếu Apache vẫn hiện phiên bản PHP cũ, máy chủ đó đang dùng mod_php; site phải chuyển sang PHP-FPM trước.

What changes compared with stock PHP-FPM

Khác gì so với PHP-FPM mặc định

  • OPcache on with sizes for Composer projects (256 MB, 50,000 files). File changes are still picked up within 2 seconds, so FTP edits and WordPress updates work as before.
  • JIT off by default. Turn it on only after measuring your own application.
  • FPM children recycle after 1,000 requests to contain leaks in old code; slowlog and status pages are on.
  • OPcache bật sẵn với dung lượng hợp cho dự án Composer (256 MB, 50.000 file). File sửa vẫn được nhận trong vòng 2 giây, nên sửa qua FTP và cập nhật WordPress vẫn như cũ.
  • JIT tắt mặc định. Chỉ bật sau khi đã đo bằng ứng dụng của bạn.
  • Tiến trình FPM được làm mới sau 1.000 request để chặn rò rỉ từ code cũ; có slowlog và trang trạng thái.

Performance

Your application boots once per worker process and then serves requests from memory. A front web server (nginx or Apache) handles TLS, HTTP/2 and static files and forwards the rest to the workers. Requires PHP 8.1 or newer.

Ứng dụng khởi động một lần cho mỗi tiến trình worker, sau đó phục vụ request ngay từ bộ nhớ. Web server phía trước (nginx hoặc Apache) lo TLS, HTTP/2 và file tĩnh, phần còn lại chuyển cho worker. Cần PHP 8.1 trở lên.

  3. Put a web server in front

    Đặt web server phía trước

    Nginx

    upstream qhturbo_myapp { server 127.0.0.1:8080; keepalive 64; }

server {
    server_name app.example.com;
    root /var/www/myapp/public;               # static files stay with nginx

    location / { try_files $uri @app; }
    location @app {
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_pass http://qhturbo_myapp;
    }
}

    Apache 2.4

    sudo a2enmod proxy proxy_http
<VirtualHost *:80>
    ServerName app.example.com
    ProxyPreserveHost On
    ProxyPass        / http://127.0.0.1:8080/ keepalive=On
    ProxyPassReverse / http://127.0.0.1:8080/
</VirtualHost>

  4. Deploy new code

    Deploy code mới

    Workers are replaced one by one. An old worker stops only after its replacement has booted, so a deploy with a syntax error leaves the old code serving and logs reload aborted.

    Worker được thay lần lượt. Worker cũ chỉ dừng khi worker mới đã khởi động xong, nên deploy có lỗi cú pháp thì code cũ vẫn chạy và log ghi reload aborted.

    sudo systemctl reload qhturbo-php85-worker@myapp   # rolling restart, no dropped requests
journalctl -u qhturbo-php85-worker@myapp -n 50       # "reload: done" or "reload aborted"

State rules for workers

Quy tắc trạng thái cho worker

With PHP-FPM everything is thrown away after each request. A worker keeps running, so anything left behind reaches the next request, possibly another user's. The runtime enforces or reports most of these rules.

Với PHP-FPM, mọi thứ bị xoá sau mỗi request. Worker thì chạy tiếp, nên thứ gì còn sót lại sẽ sang request sau, có thể của người dùng khác. Runtime tự xử lý hoặc báo lỗi cho phần lớn các quy tắc này.

RuleQuy tắcWhat the runtime doesRuntime làm gì
Keep request data out of globals and static propertiesKhông để dữ liệu request trong biến global hay static propertyNew globals are removed and logged; static properties that keep growing are reported.Biến global mới bị xoá và ghi log; static property cứ lớn dần thì bị báo.
Services with per-request data implement ResetInterfaceService giữ dữ liệu theo request phải implement ResetInterfacereset() runs after every request.reset() chạy sau mỗi request.
No exit() / die(); return a responseKhông exit() / die(); hãy trả responseThe worker is restarted, but that request fails.Worker được khởi động lại, nhưng request đó bị lỗi.
Set headers and cookies on the Response, not with header() / echoĐặt header, cookie trên Response, không dùng header() / echoqht-doctor --scan lists the places to change.qht-doctor --scan liệt kê các chỗ cần sửa.
Do not change ini settings, timezone or locale per requestKhông đổi ini, timezone, locale theo requestChanged ini settings are restored.ini bị đổi được khôi phục.
Never leave a database transaction openKhông để transaction mở sau requestThe MySQL client and the Laravel adapter roll it back and log it.Client MySQL và adapter Laravel tự rollback và ghi log.
With --concurrency above 1, use only async I/OVới --concurrency lớn hơn 1, chỉ dùng I/O asyncPDO, file_get_contents() on URLs and sleep() block the whole worker.PDO, file_get_contents() với URL và sleep() chặn cả worker.

WordPress and code that relies on exit() or globals belong in Compatible mode.

WordPress và code dựa vào exit() hoặc biến global nên dùng chế độ Compatible.

Examples

Ví dụ

Each example is a complete app.php for qhturbo-serve. The API, MySQL, Redis, transaction and reset examples were run against PHP 8.5.12, MySQL and Redis before publishing.

Mỗi ví dụ là một app.php hoàn chỉnh cho qhturbo-serve. Các ví dụ API, MySQL, Redis, transaction và reset đã được chạy thử với PHP 8.5.12, MySQL và Redis trước khi đăng.

The smallest useful app: routes, JSON responses, a 404. Data loaded above return is shared by every request.

Ứng dụng nhỏ nhất có ích: route, response JSON, trang 404. Dữ liệu nạp phía trên return được dùng chung cho mọi request.

<?php
// app.php: everything above `return` runs ONCE per worker.
use QHTurbo\Runtime\Http\{Request, Response};

$products = [1 => 'Coffee', 2 => 'Tea'];   // loaded once, reused by every request

return function (Request $request) use ($products): Response|array {
    return match ($request->path()) {
        '/' => Response::text("Hello from QHturbo\n"),
        '/products' => ['items' => $products],            // arrays become JSON
        '/echo' => ['method' => $request->method, 'body' => $request->parsedBody()],
        default => Response::json(['error' => 'Not found'], 404),
    };
};

Non-blocking MySQL and Redis with connection pools. ? placeholders are escaped; arrays expand for IN (?). Outside a worker the same calls simply block.

MySQL và Redis không chặn, có pool kết nối. Tham số ? được escape; mảng tự mở rộng cho IN (?). Ngoài worker, các lệnh này chạy kiểu chặn bình thường.

<?php
use QHTurbo\Runtime\Http\Request;
use QHTurbo\Runtime\Mysql\Client as Mysql;
use QHTurbo\Runtime\Redis\Client as Redis;
use function QHTurbo\Runtime\Async\{all, async};

// Connection pools: created once per worker.
$db    = new Mysql('mysql://app:secret@127.0.0.1:3306/shop?pool=16');
$redis = new Redis('redis://127.0.0.1:6379/0', poolSize: 16);

return function (Request $r) use ($db, $redis): array {
    if (($cached = $redis->get('dashboard')) !== null) {
        return json_decode($cached, true);
    }
    // Both queries run at the same time on two pooled connections.
    [$users, $orders] = all([
        async(fn () => $db->query('SELECT id, name FROM users WHERE id IN (?)', [[1, 2, 3]])->rows),
        async(fn () => $db->query('SELECT COUNT(*) FROM orders WHERE created_at > ?', [new DateTime('-1 day')])->value()),
    ]);
    $data = ['users' => $users, 'orders_today' => $orders];
    $redis->set('dashboard', json_encode($data), 'EX', 30);
    return $data;
};

A transaction left open is rolled back automatically when the connection goes back to the pool, so one request can never leak it into the next.

Transaction còn mở sẽ được rollback tự động khi kết nối trả về pool, nên một request không thể để nó rò sang request sau.

<?php
use QHTurbo\Runtime\Http\Request;
use QHTurbo\Runtime\Mysql\{Client, Connection};

$db = new Client('mysql://app:secret@127.0.0.1:3306/shop');

return function (Request $r) use ($db): array {
    // COMMIT when the function returns, ROLLBACK when it throws.
    $db->transaction(function (Connection $tx) {
        $tx->query('UPDATE accounts SET balance = balance - ? WHERE id = ?', [10, 1]);
        $tx->query('UPDATE accounts SET balance = balance + ? WHERE id = ?', [10, 2]);
    });
    return $db->query('SELECT id, balance FROM accounts ORDER BY id')->rows;
};

Call several internal services at once. Start the worker with --concurrency=64 so it serves other requests while it waits.

Gọi nhiều dịch vụ nội bộ cùng lúc. Chạy worker với --concurrency=64 để nó phục vụ request khác trong lúc chờ.

<?php
// Three internal services called at the same time: the request takes
// as long as the slowest call, not the sum. Run with --concurrency=64.
use QHTurbo\Runtime\Http\{Client, Request};
use function QHTurbo\Runtime\Async\{all, async, timeout};

return function (Request $request): array {
    $results = all([
        'users'  => timeout(async(fn () => Client::get('http://users.internal/api')), 1.0),
        'orders' => timeout(async(fn () => Client::get('http://orders.internal/api')), 1.0),
        'stats'  => timeout(async(fn () => Client::get('http://stats.internal/api')), 1.0),
    ]);
    return array_map(fn ($r) => json_decode($r['body'], true), $results);
};

Return an object with handle(); if it implements ResetInterface, the worker calls reset() after every request.

Trả về object có handle(); nếu object implement ResetInterface, worker gọi reset() sau mỗi request.

<?php
use QHTurbo\Runtime\Http\{Request, Response};
use QHTurbo\Runtime\State\ResetInterface;

// A service that holds per-request data must forget it after each request,
// or the next visitor would see it.
final class CurrentUser implements ResetInterface
{
    public ?string $name = null;
    public function reset(): void { $this->name = null; }
}

final class App implements ResetInterface
{
    public function __construct(private CurrentUser $user) {}

    public function handle(Request $r): Response
    {
        $this->user->name ??= $r->query['user'] ?? null;
        return Response::text('Hello ' . ($this->user->name ?? 'guest') . "\n");
    }

    public function reset(): void { $this->user->reset(); }   // called after every request
}

return new App(new CurrentUser());

Tested with Laravel 13 and Symfony 8.1. After every request the Laravel adapter resets auth, session, cookies, config, locale and open transactions; Symfony resets its kernel.reset services.

Đã test với Laravel 13 và Symfony 8.1. Sau mỗi request, adapter Laravel reset auth, session, cookie, config, locale và transaction đang mở; Symfony reset các service kernel.reset.

# No code changes. The framework boots once per worker.
qhturbo-serve /var/www/laravel --framework=laravel --workers=4 --max-requests=5000
qhturbo-serve /var/www/symfony --framework=symfony --workers=4

# Recommended: sessions and cache in Redis or files (not "array"),
# php artisan optimize (Laravel) / cache:warmup (Symfony), trusted proxies.

A first step for code that reads superglobals. Fix what --strict-state reports, then move to the Request object.

Bước đầu cho code đọc superglobals. Sửa những gì --strict-state báo, rồi chuyển sang dùng object Request.

# Older code that reads $_GET/$_POST/$_SERVER: fill superglobals per request
# (one request at a time per worker), and report state leaks loudly on staging.
qhturbo-serve legacy-front-controller.php --workers=4 --concurrency=1 \
    --superglobals --strict-state

Tools

Công cụ

qht-doctor

Checks the PHP install and scans code for patterns that break in a long-lived worker.

Kiểm tra bản cài PHP và quét code tìm những chỗ sẽ lỗi khi chạy trong worker lâu dài.

# Check the PHP install (OPcache, Xdebug, EOL, extensions)
/opt/qhturbo/8.5/bin/php /opt/qhturbo/8.5/share/qhturbo/qht-doctor.php
# Scan an application for code that is risky in a long-lived worker
/opt/qhturbo/8.5/bin/php /opt/qhturbo/8.5/share/qhturbo/qht-doctor.php --scan=/var/www/myapp

fpm-tune

Suggests pm.max_children from your RAM and the real memory use of FPM workers, so the server does not swap.

Gợi ý pm.max_children từ RAM và mức RAM thực tế của từng tiến trình FPM, để máy không bị swap.

python3 /opt/qhturbo/8.5/share/qhturbo/fpm-tune.py          # measures running FPM workers
python3 /opt/qhturbo/8.5/share/qhturbo/fpm-tune.py --worker-rss 60   # or assume 60 MiB each

install-ext

Installs PECL extensions (redis, imagick, apcu…) for a QHturbo PHP, falling back to GitHub releases when PECL is unreachable. Run it from the repository folder.

Cài extension PECL (redis, imagick, apcu…) cho PHP của QHturbo, tự lấy từ GitHub khi không vào được PECL. Chạy trong thư mục repo.

sudo scripts/install-ext.sh redis --php=8.5
sudo scripts/install-ext.sh imagick --php=8.5 --version=3.7.0

Troubleshooting

Xử lý lỗi

502 Bad Gateway or 503 after switching a site502 Bad Gateway hoặc 503 sau khi chuyển site

Usually the web server user cannot open the PHP-FPM socket, which is readable only by the user given to install.sh --user. Compare the two, then reinstall with the right user, or restore the old configuration line.

Thường là do user của web server không mở được socket PHP-FPM, vì socket chỉ cho user đã truyền vào install.sh --user. So sánh hai user, rồi cài lại với user đúng, hoặc khôi phục dòng cấu hình cũ.

# Is the web server user allowed to open the socket?
ls -l /run/qhturbo/php85-fpm.sock          # owner/group, mode 0660
ps -o user= -C nginx -C apache2 -C httpd | sort -u
# Reinstall with the web server's user (www-data on Debian/Ubuntu, apache on AlmaLinux, www on aaPanel)
sudo -E scripts/install.sh --user=www-data --group=www-data
"Error establishing a database connection" after switching a site"Không kết nối được database" sau khi chuyển site

Installs made before 2026-10-22 started PHP-FPM with systemd's PrivateTmp, which hides the real /tmp. aaPanel's MySQL listens on /tmp/mysql.sock, used whenever the database host is localhost. Remove the setting and restart:

Bản cài trước ngày 2026-10-22 chạy PHP-FPM với PrivateTmp của systemd, khiến PHP không thấy thư mục /tmp thật. MySQL của aaPanel nhận kết nối qua /tmp/mysql.sock, được dùng mỗi khi host database là localhost. Bỏ tuỳ chọn này rồi khởi động lại:

# Remove PrivateTmp from the service (fixed in the repository on 2026-10-22)
sudo sed -i '/^PrivateTmp=/d' /etc/systemd/system/qhturbo-php85-fpm.service
sudo systemctl daemon-reload && sudo systemctl restart qhturbo-php85-fpm
ls -l /tmp/mysql.sock      # aaPanel's MySQL socket
"--workers needs pcntl_fork …""--workers needs pcntl_fork …"

Your php.ini blocks pcntl_* in disable_functions (aaPanel and many panels do this). Load the Performance ini, which allows only the functions workers need.

php.ini đang chặn pcntl_* trong disable_functions (aaPanel và nhiều panel làm vậy). Hãy nạp ini của chế độ Performance, ini này chỉ mở đúng các hàm worker cần.

# Workers need the Performance ini, which re-allows pcntl_fork & co:
PHP_INI_SCAN_DIR=/opt/qhturbo/8.5/etc/conf.d:/opt/qhturbo/8.5/etc/performance.d \
    /opt/qhturbo/8.5/bin/php /opt/qhturbo/8.5/share/qhturbo-runtime/bin/qhturbo-serve app.php --workers=4
# (the systemd unit qhturbo-php85-worker@.service already sets this)
Uploads fail in a worker with move_uploaded_file()Upload lỗi trong worker khi dùng move_uploaded_file()

move_uploaded_file() and is_uploaded_file() only accept files created by PHP-FPM's own upload handling. Laravel and Symfony UploadedFile objects work; plain PHP code should use rename().

move_uploaded_file() và is_uploaded_file() chỉ nhận file do PHP-FPM tạo khi upload. UploadedFile của Laravel và Symfony vẫn chạy; code PHP thuần nên dùng rename().

// move_uploaded_file() only works under PHP-FPM. In a worker:
$file = $request->uploadedFiles()['photo'];
rename($file['tmp_name'], '/var/www/uploads/' . basename($file['name']));
A worker restarts after every requestWorker khởi động lại sau mỗi request

Check --memory-limit: it must be larger than what your framework uses after booting (Laravel often needs 60–100 MB). The log line draining (memory … over limit) confirms it.

Kiểm tra --memory-limit: phải lớn hơn mức RAM framework dùng sau khi khởi động (Laravel thường cần 60–100 MB). Dòng log draining (memory … over limit) xác nhận điều này.

Large downloads use a lot of worker memoryTải file lớn làm worker tốn nhiều RAM

Responses are built in memory before sending, including streamed and file responses. Let the front web server send big files (static files or X-Accel-Redirect).

Response được dựng hết trong RAM trước khi gửi, kể cả response dạng stream và file. Hãy để web server phía trước gửi file lớn (file tĩnh hoặc X-Accel-Redirect).

DirectAdmin, cPanel, LiteSpeed, Plesk?DirectAdmin, cPanel, LiteSpeed, Plesk?

Not automated yet. These panels give each hosting account its own Linux user, and a safe setup needs one PHP-FPM pool per account. That support, and builds for AlmaLinux/Rocky, are the next items on the roadmap. Please open an issue with your panel and OS so it can be tested on real servers.

Chưa có tự động. Các panel này cấp cho mỗi tài khoản hosting một user Linux riêng, và cách chạy an toàn cần một pool PHP-FPM cho mỗi tài khoản. Phần hỗ trợ này cùng bản build cho AlmaLinux/Rocky là các việc tiếp theo trong lộ trình. Hãy mở issue ghi panel và hệ điều hành của bạn để có thể test trên server thật.
